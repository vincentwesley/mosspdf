# Decisions

## D1. Name: MossPDF, 2026-11-19 (renamed 2026-11-21, see D23)
The product was first called "Paper Desk", dropped because "PaperDesk" is an existing iPad note-taking app by WebSpinner LLC that imports PDFs ([App Store](https://apps.apple.com/us/app/paperdesk/id367563434)), a real confusion risk for a PDF tool. A second name was then chosen and used until 2026-11-21, when it was replaced by MossPDF because another app already uses that earlier name. Not a legal clearance; LEGAL-REVIEW.md repeats the check.

## D2. Hosting: Cloudflare Workers static assets (moved to Cloudflare Pages in D23)
Owner preference, and it can send real headers (CSP with `frame-ancestors`, COOP/COEP for `crossOriginIsolated`, Permissions-Policy) that GitHub Pages can't. No Worker script: static assets only. Deploy with local `wrangler deploy` (already authenticated).

## D3. Licence: MIT, `Copyright (c) 2026 Vin's Atelier`
All runtime dependencies are MIT, BSD, ISC or Apache-2.0. AGPL engines (MuPDF, Ghostscript) are excluded. The logo stays all rights reserved (NOTICE.md).

## D4. Engines
pdf.js for rendering and text positions; @cantoo/pdf-lib for assembly, forms, drawing; EmbedPDF PDFium WASM for true redaction (pending spike); qpdf WASM for check/repair/linearize; tesseract.js for OCR. Details and licences in RESEARCH.md §8.

## D5. HEIC: native decode only
Every permissive-looking HEIC decoder bundles LGPL libheif. MossPDF accepts HEIC only where the browser decodes it itself (Safari), and otherwise says "convert to JPG first".

## D6. NRIC/FIN M-series: format match only
The M-series check-letter rule isn't published; S/T/F/G use the documented checksum. Unverified M numbers are still flagged for review (better a false positive the user unticks than a missed ID).

## D7. Seal after preload
The header CSP allows only same-origin requests, so no third party can ever be reached. On top of that, the app preloads all engines (served from the service-worker cache after the first visit) and then seals itself with a meta CSP that blocks fetch, scripts and new workers (`docs/spikes/csp.md`). Workers that exist before the seal are not covered by the meta, so they are either created after the seal (blob URLs, WASM bytes passed in by message) or served with a `connect-src 'none'` header. Files can be opened before the seal finishes; until then the header CSP is the guarantee, and the panel says so honestly. Rejected: sealing before any engine loads (every tool would need a reload), and loading packs lazily after sealing (impossible by design).

## D8. Face detection is not decided yet
MediaPipe's WASM is about 29 MB raw. That is too heavy to preload for one tool. In M6 a lighter, permissive detector will be evaluated. If none is reliable, photo mode ships EXIF/GPS stripping plus manual blur boxes and says auto-detection is not included.

## D9. Engine split (from the spike)
Redaction and text search use PDFium (`EPDFText_RedactInRect` + `FPDFPage_GenerateContent`). Metadata and XMP scrubbing use pdf-lib (PDFium has no XMP API). Encryption and decryption use qpdf WASM, which writes R6 AES-256. Every redacted export is checked with a `qpdf --qdf` needle scan before it is offered for download. The qpdf WASM package bundles qpdf 12.2.0.

## D10. Page assembly: qpdf WASM, pdf-lib for repair and metadata (2026-11-19)
Compared `qpdf --empty --pages ... --` (qpdf-wasm 12.2.0) with pdf-lib `copyPages` on the generated corpus (`tests/corpus/README.md`):

| Check | qpdf WASM | pdf-lib copyPages |
|---|---|---|
| AcroForm kept on page copy | yes (`/AcroForm` present; duplicate field names renamed on merge, 10 widgets / 8 unique names) | no: widgets stay but `/AcroForm` is dropped, so the fields are dead |
| Links, annotations | kept (URI, GoTo, Text) | kept |
| Outlines | dropped (reported as a warning) | dropped |
| Encrypted input with password (AES-256, RC4-40) | ok | ok |
| Mixed sizes, /Rotate | ok | ok |
| broken-xref, truncated | **fails: this 12.2.0 wasm build cannot rebuild a damaged xref** (the 12.4.2 CLI repairs both, exit 3) | opens, 3 pages |
| corrupt (600 random bytes) | fails (same reason) | opens but silently keeps 1 of 3 pages |
| 1,000 pages | 370 ms | 1,470 ms |

Verdict: the premise "qpdf repairs damaged files" does not hold for the WASM build, so the decision is split. qpdf WASM does the assembly (forms kept, fastest, handles rotate and password input; output is unencrypted). When qpdf cannot open a file, pdf-lib loads and re-saves it (writing a fresh xref, blanking pages whose content stream was cut off) and qpdf continues from that copy; the user gets a `repaired` warning. pdf-lib also sets Producer/Creator after assembly, because qpdf `--update-from-json` replaces the whole trailer (a partial update loses /Size and /Root), which makes it unsafe for a one-field change. `--empty` output carries no Info, so with the credit off nothing needs removing. Cost: the credit pass re-parses the output with pdf-lib (about 1.5 s for 1,000 pages). Revisit when qpdf-wasm ships a build with working xref recovery.

D10 follow-up (same day): checked whether the wasm failures were exit code 3 mistaken for an error. They are not. On broken-xref, truncated and corrupt, `callMain` returns 2 (nothing thrown), no output file is written, and stderr lacks the "Attempting to reconstruct cross-reference table" line the 12.4.2 CLI prints before it succeeds with exit 3. `--warning-exit-0` changes nothing (same rc 2, no output). So qpdf 12.2.0 aborts before its repair path in this build and there is nothing to accept as a success; the pdf-lib re-save stays as the repair step. A wrapper that treated exit 3 plus an existing output as success is still correct and already what `assemble` does (it only fails on code 2 or a missing file), so a newer qpdf-wasm would take over repair with no code change.

## D11. M1 integration notes (2026-11-19)
- qpdf-wasm 0.3.1 ignores `wasmBinary` and fetches `qpdf.wasm` itself, which the ops worker's `connect-src 'none'` blocks. In a worker `createQpdf` answers that one fetch from memory (`src/engines/qpdf.ts`); Node still reads the file from disk. Any later fetch from the worker still hits the CSP.
- The `/assets/workers/*` rule is merged with `/*` by Cloudflare: both CSPs are sent, joined with a comma, so the browser applies both and `connect-src 'none'` wins. `tests/headers.expected.json` records the joined value and `tests/headers.test.ts` checks it against `public/_headers`.
- `parseRanges` lives in `src/ops/ranges.ts` (imports only `PdfError`), so the main bundle never pulls pdf-lib; `npm run check:budgets` fails if pdf-lib code appears in the main-thread chunks.
- Single-PDF tools (split, organize, extract) work on the newest file. Adding another replaces it, with a closable "Replaced X. Undo" toast and a hint to Merge.
- The favicon SVG may not carry a `<style>` element: WebKit applies the page CSP to it (`style-src 'self'`).
- Playwright's iPhone WebKit on a display-scaled Windows machine reports `clientWidth` 312 for a 390 layout (a bare page shows it too), so `expectNoOverflow` compares `scrollWidth` with the layout width of `<html>` (1px tolerance).
- Playwright runs 3 workers locally: six parallel browsers with WASM and pdf.js crash Firefox content processes on a 16 GB machine.
- Liberation Sans was dropped from the pdf.js data pack: see D22.

## D12. Image recompression: MozJPEG WASM passed as bytes (2026-11-19)
`compress` (balanced/strong) re-encodes embedded images as JPEG, so it needs an image codec in the ops worker and in Node tests. Chosen: `@jsquash/jpeg` 1.6.0 (Apache-2.0, MozJPEG compiled to WASM, from Squoosh). Its `init(WebAssembly.Module)` takes a compiled module, so both binaries (decoder 163 KB, encoder 246 KB) are fetched before the seal with the qpdf wasm and sent to the worker in the same `init` message; nothing is fetched afterwards (unlike qpdf-wasm, no fetch patch is needed). The same code runs in Node (tests read the wasm from node_modules). Rejected: an injected OffscreenCanvas codec (not isomorphic, so the Node tests would exercise a stand-in, and canvas colour management can alter pixels). `Engines` gains `jpeg: Jpeg` (`src/engines/jpeg.ts`).
- Pipeline: pdf-lib pass (images, credit) then qpdf `--object-streams=generate --recompress-flate --compression-level=9`. Light = qpdf only (pdf-lib only when the credit is on). If the result is not smaller the original bytes come back with a `not-smaller` warning.
- Images touched: 8-bit DeviceRGB/DeviceGray/ICCBased(N 1 or 3), Flate (incl. PNG predictors) or DCT or raw, at least 10,000 px. The declared colour space is kept, so colours do not shift. Skipped: SMask/Mask/Matte/Decode, image masks, CMYK, Indexed, JBIG2, JPX, 16-bit, anything that fails to decode. A replacement is used only when smaller than the original stream.
- Levels cap the longest side at 1600 px (q75) or 1000 px (q55), box-filter downsample. Cap is in pixels, not DPI (placement would need content-stream parsing).
- On the 19.5 MB image-heavy fixture (5 noise pages): light 19.51 MB, balanced 3.07 MB (15.8%), strong 1.06 MB (5.4%).
- Other M2 ops decisions: stamps (page numbers, watermark) use Helvetica/WinAnsi and are placed in displayed space (CropBox, /Rotate); non-WinAnsi text is rejected with the characters named (Unicode fonts later). Page numbers count the selected pages (`{total}` is the last number shown). Edits of an existing file set Producer only (Creator is the author's program); `imagesToPdf` sets both. `removeAll` adds no credit and a qpdf rewrite purges the old Info/XMP objects. Encrypted inputs are opened with the password and written decrypted, with a `decrypted` warning.

## D13. Passwords and safety (M3, 2026-11-19)
- **No circumvention.** Passwords are only added or removed when the user supplies the right password for their own file. No cracking, guessing, candidate lists or brute force exist in the code, and no owner-password bypass.
- **Who may remove protection.** qpdf's `--json=2` `encrypt` block says which password matched (`ownerpasswordmatched`, `userpasswordmatched`) and lists `capabilities`. Rule in `authorise()` (`src/ops/protect.ts`): the owner password always may; the user password (or none, for a file that opens without one) only if every capability is allowed. A file that opens freely but restricts print/copy/edit therefore needs its owner password to unlock; missing or wrong gives `wrong-password`. qpdf alone would decrypt with the user password, so the check is ours and runs before every decrypt. The same rule guards `protect` (re-encrypting changes restrictions), `cleanCopy` and `repair` (both write an unencrypted copy). The safety scan is read-only and only needs a password that opens the file.
- **Protect** uses `--encrypt --user-password=U --owner-password=O --bits=256 ... --` (named options, qpdf 11.7+, so a password starting with `-` is never read as an option; reading passwords use `--password=P`) (AES-256, R6). An empty owner password reuses the user password (warned). An empty user password is rejected: the file would not be protected. Permissions map to `--print`, `--extract`, `--assemble`+`--modify-other` (modify), `--annotate`, `--form`; accessibility extraction stays allowed.
- **Scan** walks qpdf's JSON (object streams are flattened by qpdf, so risks inside them are found; `/ObjStm` itself is counted from raw bytes because JSON hides it). Nested inline dictionaries are examined, and each item carries the page (first page that reaches it) or "document". Wording describes what an element can do, never that a file is malicious.
- **Clean copy** deletes `/A` actions that are JavaScript, Launch, SubmitForm, ImportData, GoToR/GoToE (and URI unless `keepLinks`, including chained `/Next`), every `/OpenAction`, `/AA`, `/JS`, `/XFA`, `/AF`, the JavaScript and EmbeddedFiles name trees and FileAttachment/RichMedia annotations with pdf-lib, then qpdf rewrites it (drops orphans, no object streams) and the result is re-scanned; leftovers produce a `residual-risk` warning. AcroForm fields are kept; submit buttons lose their action (warned).
- **Repair** is `openPdf` (D10) plus a qpdf rewrite, returning `actions`, `pagesBefore` (a lower-bound guess from page objects in the raw bytes, only for damaged plain files), `pagesAfter` and `complete=false` plus a `pages-lost` warning when pages disappeared.

## D12. Tool modules and one shared workspace (2026-11-19)
Each tool is `src/tools/<id>.ts` exporting a `ToolDef` (type in `src/tools/types.ts`); `src/ui/workspace.ts` renders everything around it (intake, file list, warnings, options, page grid, output settings, action bar, results, zip, job runner). `src/tools/index.ts` lists the tools; the home map reads it. A tool without `run` is planned: a dashed "Coming soon" tile on home, and its route shows intake only. To make one live, edit its own file only. Intake kinds: `pdf` (one, replaced with undo), `pdfs`, `images` (JPG, PNG, WebP; HEIC only if the browser decodes it, else "convert to JPG first"), `pdf-pair` (Original / Changed, newest two kept). Images are decoded with `createImageBitmap(blob, { imageOrientation: "from-image" })` into upright width/height plus a small preview drawn on a canvas (a `blob:` img would be blocked by the sealed CSP); the original Blob is kept, nothing is persisted. Zip downloads use fflate, imported statically: after the seal the meta CSP forbids loading new scripts, so a lazy chunk would fail.

## D14. Workers must be running before the seal (Firefox, 2026-11-19)
Symptom: a `worker-src` CSP violation on page load in Firefox, seen twice in a full e2e run, only under load; never in Chromium or WebKit. Cause: `new Worker(url)` returns before the script is fetched. Chromium checks `worker-src` at construction; Firefox checks it when the script actually loads. The pdf.js worker (`src/core/engines.ts`) was created and then never awaited (the ops worker was, through its `init` call), so on a slow machine the seal meta (`worker-src 'none'`) could land first and block the worker's own script. Reproduced deterministically by delaying `/assets/workers/pdf.worker-*.js` by 2.5 s (`e2e/seal-race.spec.ts`): Firefox fetched the script after `mosspdf:sealed` (the fixture's "request after seal"); without the delay that same fetch is the violation. Fix: wait for pdf.js's own `ready` message from the worker before the engine counts as loaded, so every worker has run its first instruction before the meta is added. Rule for new engines: a worker is only "loaded" once it has answered a message (`init` call or equivalent), never just constructed. The test fixture now also reports the violation's source file, line, seal state and time. Also `PH_PORT` in `playwright.config.ts` moves the local server off 4811 so worktrees can run e2e side by side.


## D16. OCR: loaded before the seal, on the OCR page only (M5, 2026-11-20)
- **Engine.** `tesseract.js-core` 7.0.0 (Apache-2.0) driven directly, not through the tesseract.js worker wrapper (which fetches and spawns things itself). `src/engines/ocr.ts` binds the SIMD+LSTM Emscripten module: `FS.writeFile` the gunzipped `eng.traineddata`, `TessBaseAPI.Init(null,"eng",1)`, write the page PNG to `/input`, `SetImageFile`, `Recognize`, then walk a `ResultIterator` at word level (text, confidence, bounding box, end-of-line and end-of-paragraph flags). Model: `@tesseract.js-data/eng` 4.0.0_best_int (2.95 MB gzip; gunzipped with `DecompressionStream` on bytes, not `Blob.stream()`, which WebKit loads through a `blob:` URL). The glue is bundled into the worker (`src/workers/ocr.worker.ts`), so no `importScripts` or eval ever runs under the CSP; the 2.86 MB `.wasm` and the model arrive by `postMessage` like the other engines (D12).
- **Loading and the seal.** About 6 MB must not cost every visitor. The seal still happens at boot after preload, so the `ocr` engine in `src/core/engines.ts` loads only when the page boots on `#/ocr`: fetch both files, create the OCR worker, await its `init` (D14), then seal. A sealed page cannot start it later (no new worker, no fetch). Opening OCR from another route therefore shows a plain note and "Load the OCR engine (about 6 MB, stays on this device)", which sets `#/ocr` and reloads the tab; it says files added in this tab will be cleared when there are any. The privacy panel states that the OCR engine, when used, was loaded before sealing (it is in the request log with the other pre-seal requests).
- **Offline.** The OCR files are left out of the service worker precache (`vite.config.ts`, `public/sw.js`) so installing the app stays small; `sw.js` stores them in the version cache the first time they are fetched, so OCR then works offline. A new app version drops that cache; the next OCR use fetches them again. Budgets raised on purpose: `.wasm` 2000 to 4700 KB (qpdf 1.3 MB + MozJPEG 0.4 MB + Tesseract 2.9 MB), new `.gz` 3100 KB.
- **Cancel.** One page is one synchronous wasm call, so the worker cannot be interrupted and is never terminated (a replacement could not be created after the seal). The tool checks its abort flag between pages and the RPC call rejects at once on Cancel; the page being read finishes in the background and the next run queues behind it.
- **Output.** Searchable PDF = the original pages untouched plus an invisible text layer added in the ops worker (`src/ops/ocr.ts`): Helvetica/WinAnsi, text render mode 3 (`Tr 3`), each word placed at its box and stretched to its width with `Tz` from `widthOfTextAtSize`; characters outside WinAnsi are dropped from the layer (the picture still shows them). Boxes are mapped through the page's displayed view (`/Rotate`, CropBox) like the stamps. Optional `.txt` from the same words. "Skip pages that already have text" (default on) uses pdf.js `getTextContent`; "Clean up scans" greys and stretches contrast on the canvas before reading. Pages are read at 200 dpi (capped at 12 megapixels).
- **Known limits.** English only. Handwriting, columns and tables are read as Tesseract sees them; there is no layout analysis beyond its own.
## D15. Fill and sign (M4, 2026-11-20)
- **Visual signature only.** Sign places a picture (PNG) of a signature, initials, a date or a line of text. It is not a certified digital signature (no certificate, no PKCS#7) and the page says so next to the main button. Real signing is out of scope: it needs keys and a trust chain the browser cannot vouch for.
- **No persistence.** A signature lives in memory in the open tab and goes with it. Nothing goes to storage, so there is no profile to leak, and the page says "Your signature is not saved anywhere."
- **Canvas, never `<img>`.** After the seal the page CSP has no `img-src`, so previews and placed pictures are drawn on `<canvas>` (`src/ui/sigmaker.ts`, `src/tools/sign.ts`). The result is a trimmed transparent PNG: drawn strokes, typed text, or an upload whose near-white background is made transparent.
- **Font.** Typed signatures use Caveat (SIL OFL 1.1, Fontsource build, `src/fonts/caveat-latin-wght-normal.woff2`, 73 KB). It loads before the seal like the other fonts (`preloadStatic`). Fill and the text/date stamps draw with Helvetica (WinAnsi), as page numbers and watermark do: other characters are refused with a plain message ("This form can't take characters like X yet"). No TTF is bundled and there is no fontkit, so embedding a Unicode font is a later step.
- **Placement is in displayed-page fractions.** `stampPage` items carry `fx, fy` (from the top left of the page as the viewer shows it, after /Rotate and CropBox) and `fw` (picture width as a fraction of the page width); text items carry the left end of the baseline and a size in pt. The op turns them into user space per page with the same `view()`/`toUser()` as page numbers. The same numbers therefore work at any zoom, on every page ("all pages" is one item) and under every rotation; tests read the result back through pdf.js and check it to 0.5 pt. The editor positions items in percent of the page and sizes text in `cqw`, so resizing the window needs no JS.
- **Page viewer** (`src/ui/pageview.ts`): pdf.js through the existing `renderThumb` queue, drawn only while near the viewport and re-drawn when the width changes. PDF rectangles (form widgets) go to the screen through `viewport.convertToViewportPoint` (rotation and CropBox included; pdf.js 6.5 has no rectangle helper). A tool mounts it inside its `options` element; `ToolDef.destroy` was added so it can release its observers.
- **Forms.** `readForm` lists fields with their widgets (page index and rectangle) using pdf-lib (`preserveXFA`); `fillForm` writes only the fields the user changed, updates their appearances with Helvetica, optionally flattens. Read-only fields are never written. The fields list and the on-page controls share one value map, so they stay in sync; the list is the accessible and phone route.
- **XFA policy.** XFA-only form (no standard fields): explain, do not fill, do not pretend; point to Acrobat Reader or a standard PDF. Hybrid (AcroForm plus XFA): fill the standard fields, delete the XFA data from the copy, and say so. Both are warned about up front, before running.
- **Signed PDFs.** `readForm.signed` looks for `/ByteRange` with `/Sig` in the raw bytes (a signature inside a compressed object stream is not seen; `prepare()` still reports `/FT /Sig`). Fill and Sign warn before running that changing the file invalidates the existing digital signature.
- **Budget.** `main-gzip` in `budgets.json` went from 40 to 46 KB: Fill and Sign (page viewer, fields list, signature maker, editor) live in the main-thread bundle, about 6 KB gzipped. pdf-lib stays in the ops worker.

## D18. Compare (M7)
- **Own diff, no dependency.** `src/core/diff.ts` is Myers on interned word arrays, linear space (middle-snake bisection). It gives up (null) over 200,000 words in total or a 60M-step budget, so two unrelated long texts cannot freeze the tab. Then Compare says so and lists whole pages (page-level diff of the page texts), with no word boxes.
- **Words.** `src/core/pagewords.ts` turns pdf.js text items (main thread, `getTextContent`) into words with user-space rects: items that continue a word are joined, a hyphen at a line end is joined with the next line ("exam-" + "ple"), whitespace is normalised (NFKC). Options Ignore case and Ignore punctuation only change the comparison key; the text shown is the original. Vertical text gets approximate boxes.
- **One diff over the whole text**, so an inserted or deleted page is just a change. Pages are paired separately (`alignPages`: diff of the page texts, then the rest in order) for the side-by-side sync and the overlay page picker. A different page count is stated next to the summary.
- **Views** (`src/ui/compareview.ts`, ARIA tablist): Changes (click jumps to both sides), Side by side (two `pageView`s, words boxed through `rectToFractions`, scrolling one column moves the other to the paired page), Overlay (`src/core/pixeldiff.ts`: both pages at the same scale on white, a pixel counts when the summed channel difference is over 96; faded Original canvas under a mark canvas, opacity slider). Colours are always paired with the words Removed/Added. Lists stop at 500 changes; the report has all.
- **No text** (scans): "These look like scans. Run OCR first" links to #/ocr; Overlay still works. With identical text, the first 60 page pairs are compared by pixels for "The text is the same, but N pages look different".
- **Report** (`src/ops/report.ts`, ops worker, pdf-lib, Helvetica WinAnsi; other characters print as "?" and the report says so). The text file is built on the main thread from the same data (`core/compare.ts`). `ToolDef.summary` replaces the "size to size" line of the result card.
- **No lazy chunks**: a sealed page cannot fetch them. `main-gzip` 46 to 49 KB.
- **CSP report on mobile-safari CI**: not reproducible locally (WebKit, mobile-safari); every pdf.js document opens through `openDoc` (`disableFontFace`), and src/ has no style strings. Still `fixme` on CI mobile-safari.
## D17. Redaction and photo clean (M6, 2026-11-20)
- **Method: rebuild, don't edit.** PDFium editing (D9) was not used. Each page with something to remove is drawn with pdf.js at 200 dpi (capped at 12 megapixels) on the main thread, the black boxes are painted on the bitmap, and the page is saved as a JPEG (canvas, quality 0.85). The ops worker replaces that page's content with the picture, same size, rotation and CropBox (`src/ops/redact.ts`). Text, vector shapes and images under a box therefore no longer exist in the file. Pages without hits are left untouched and stay vector.
- **Hidden text layer.** The words of an affected page are added back invisibly (render mode 3, the OCR layer, `drawLayer` in `src/ops/ocr.ts`), minus every word that touches a box. Text outside the boxes stays searchable and copyable; the result note says so.
- **What is stripped from the whole file** (not only affected pages): Info and XMP, all annotations (links and comments included) and the AcroForm, EmbeddedFiles and JavaScript name trees, OpenAction/AA, structure tree, thumbnails and page-piece data on rebuilt pages. Outline entries stay but a title that contains a redacted string becomes "[redacted]". Then qpdf rewrites the whole file (no incremental history, only reachable objects, so the old pages, fonts and images are dropped).
- **Verification before saving.** The finished file goes through `qpdf --qdf --object-streams=disable` and is searched (case-insensitive; plain, UTF-16BE and hex forms; picture data skipped) for every redacted string. One left means an error and no file. Strings that are still readable on purpose (the same text on an unredacted page, or a word the user left unticked elsewhere) are left out of the check.
- **Detectors** are pure functions (`src/core/detect.ts`): NRIC/FIN S/T/F/G with the check letter (M format-only and flagged "check this one", D6), SG phone numbers (+65 optional, 8 digits starting 3, 6, 8 or 9), emails, block/street addresses with unit numbers and postal codes, postal codes next to "Singapore" or "S(". Search is case-insensitive with a whole-word option. Positions come from pdf.js text items mapped through the viewport (`src/core/textpos.ts`), so rotation and CropBox work. They are aids: the user reviews every hit, and hand-drawn boxes cover the rest. Hits are shown partly masked in the list.
- **Drawing boxes.** Mouse and pen drag on a page; touch uses "Add box" so the page still scrolls. Boxes move with arrows, resize with plus/minus and Alt+arrows, Delete removes (WCAG 2.5.7). Shared by redact and photo (`src/ui/boxlayer.ts`).
- **Photo clean.** The photo is decoded upright (`createImageBitmap` with `imageOrientation: "from-image"`), blurred or pixelated inside the boxes on a canvas, and saved again from the canvas (JPEG 0.92, PNG for PNG), which writes no EXIF, GPS, XMP or thumbnail. A minimal EXIF reader (`src/core/exif.ts`: make, model, date, GPS present) shows what was found. HEIC follows the image intake rules (D5). Very large photos are scaled to 16 megapixels. Pixelate is the default because a light blur can be partly undone; blur falls back to pixelate where the canvas has no `filter`.
- **No automatic face or plate detection (D8 resolved).** No small, permissive, verified model was found, and MediaPipe is too heavy to preload for one tool. The page says: "Draw boxes over faces, number plates or screens. MossPDF doesn't detect them automatically."
- **Limits.** Redacted pages are JPEG pictures (softer text, larger file). Encrypted input must be unlocked first; the copy has no password. A digital signature is invalidated (warned up front). Latin text only in the hidden layer (WinAnsi, as OCR).
- **Budget.** `main-gzip` 46 to 52 KB: redact and photo clean (detectors, text layout, box layer, EXIF reader) live in the main-thread bundle.
## D19. Palette, workflows, batch, accessibility check (M8)
- **Palette** (`src/ui/palette.ts`): native `<dialog>`, input `role=combobox` with `aria-controls`/`aria-activedescendant` over a `role=listbox` of `role=option`; ArrowUp/Down, Enter, Esc, click. Ranking is `scoreTool` in `core/toolsearch.ts` (title word start > title > blurb or group > letters in order, words of 3+ letters), shared idea with the home filter (`matchTool` unchanged). Commands: Switch theme, Privacy log, Clear all files (with undo toast). Ctrl/Cmd+K works anywhere; `?` (shortcuts list) never fires while typing in a field and neither opens over another open dialog. Focus returns to the opener, except after navigating, where the route change focuses the new heading. A visible "Search tools" header button shows the shortcut (hidden on touch-only devices).
- **Workflows** are normal tools in a new first group "Workflows", one file each (`wf-email`, `wf-share`, `wf-apply`) because the e2e home check derives tiles from file names. The chain runner is `core/workflows.ts` (pure, unit-tested): steps run in order through `ctx.call` (same ops as the single tools), Cancel is checked between steps (the ops also stop), and each step reports state and a plain line to `ui/steplist.ts`, which stays visible after the run as the record of what happened. Application pack: merge, page numbers bottom middle ("Page n of N"), optional balanced compress. **Mixed intake is not supported** (one workspace kind per tool), so the pack takes PDFs only and links to Images to PDF.

- **Budget**: `main-gzip` 58 to 62 KB (four tools, palette, step list, report text).

## D20. Unicode text: Noto Sans subset via fontkit in the ops worker (2026-11-21)
- Text beyond WinAnsi (Vietnamese, Polish, Turkish, Greek, Cyrillic) works in fill, page numbers, watermark, sign text/date, OCR layer and the compare report. `src/ops/ufont.ts` `pickFont` keeps Helvetica when every character is WinAnsi (common case, no size change) and otherwise embeds the Unicode font with `@cantoo/fontkit` 2.0.12 (`registerFontkit`, `subset: true`, so only used glyphs are written). Characters the font lacks (CJK, Tamil, emoji) are still refused by name; the report keeps its "?" fallback.
- Font: Noto Sans Regular (OFL) cut to Latin, Latin Extended, Vietnamese, Greek, Cyrillic, punctuation, currency with `pyftsubset` (`src/fonts/notosans-unicode-400-normal.ttf`, 179 KB). No bold in the report when the Unicode font is used.
- Loading follows D7/D15: fetched with the qpdf engine before the seal and passed in the ops `init` message; fontkit lives only in the ops worker bundle. The client gate (`src/core/winansi.ts`, `UNICODE_OK`) is the same ranges as plain regexes, so the main bundle stays free of pdf-lib/fontkit.
- Gotcha: `ccmp` is turned off. It decomposes "ị" into glyphs with no code point, which writes empty `<>` entries in the ToUnicode map and pdf.js extracts garbage. Also fixed: the OCR layer used the literal font name `/PHO`, but pdf-lib returns a suffixed name.

## D22. Liberation Sans dropped (2026-11-21)
